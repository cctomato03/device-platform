# 插件开发规范

> 面向：插件作者（自研功能、第三方应用二次开发）。
> 目标：**任何语言、任何既有程序，只要满足本规范，就能被平台以统一方式安装、配置、启停、看日志、卸载。**

---

## 1. 插件包结构

插件包是一个 `.zip` 或 `.tar.gz`，解压后**根目录必须有 `manifest.json`**：

```
my-plugin/
├─ manifest.json          # 清单（必填，平台唯一识别入口）
├─ bin/                   # 可执行文件（runtime=process 必填）
│  └─ my-daemon
├─ templates/             # 配置文件模板（configFiles 引用的模板放这里）
│  └─ app.conf.tmpl
└─ README.md              # 建议：使用说明、参数含义、排障
```

打包命令（平台自带）：

```bash
bash scripts/pack-plugin.sh plugins-src/frp        # 产出 dist/plugins/frp-1.0.0.zip
```

> 平台自带插件放在仓库 `plugins-src/<id>/`，安装脚本会复制到设备 `<home>/plugins-bundled/`，
> 在「插件市场 → 可安装」里一键安装。

## 2. manifest.json 字段规范

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "vendor": "acme",
  "category": "network",
  "description": "一句话说明这个插件解决什么问题",
  "icon": "ri:apps-2-line",
  "homepage": "https://example.com",
  "license": "Apache-2.0",
  "arch": ["amd64", "arm64"],
  "runtime": "process",
  "entry": "bin/my-daemon",
  "args": ["-c", "{{ .platform.dataDir }}/conf/app.conf"],
  "restartPolicy": "on-failure",
  "healthCheck": { "type": "none", "intervalSec": 15 },
  "configFiles": [
    { "path": "{{ .platform.dataDir }}/conf/app.conf", "template": "app.conf.tmpl", "mode": "0600" }
  ],
  "schema": [
    { "key": "listenAddr", "label": "监听地址", "type": "string", "default": "0.0.0.0:8080", "required": true }
  ],
  "ports": [8080],
  "privileged": false
}
```

### 2.1 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 插件唯一标识，`^[a-z0-9][a-z0-9-]{1,31}$`；同时作为目录名 `plugins/<id>/`、`plugin-data/<id>/` |
| `name` | ✅ | 展示名称（中文优先） |
| `version` | ✅ | 语义化版本 `x.y.z`；同 id 不同版本可共存于包目录，安装即升级 |
| `vendor` | | 厂商/作者 |
| `category` | | `network` / `storage` / `ai` / `media` / `device` / `security` / `tool` |
| `description` | | 列表页展示，建议 40～120 字，说清「做什么 + 依赖什么」 |
| `icon` | | Iconify 名称（`ri:xxx` / `ep:xxx`），为空用默认图标 |
| `arch` | | 支持架构白名单；为空表示不限。例 `["amd64","arm64"]` |
| `runtime` | ✅ | `process`（原生进程）或 `docker`（容器） |
| `entry` | process ✅ | 可执行文件相对路径，如 `bin/frpc`；平台会补可执行权限 |
| `args` | | 启动参数数组，支持模板变量（见 §4） |
| `docker` | docker ✅ | 见 §2.3 |
| `restartPolicy` | | `always` / `on-failure`（默认）/ `never` |
| `healthCheck` | | 目前支持 `type: none | tcp`、`port`、`intervalSec` |
| `configFiles` | | 由平台渲染的配置文件列表，见 §2.2 |
| `schema` | ✅ | 配置表单定义，平台据此**自动生成界面**，见 §3 |
| `ports` | | 占用的端口（用于展示与冲突提示，不参与网络配置） |
| `privileged` | | 是否要求特权（前端会提示风险） |

### 2.2 configFiles（配置文件渲染）

| 字段 | 说明 |
| --- | --- |
| `path` | 目标落盘路径，必须落在插件数据目录内，支持 `{{ .platform.dataDir }}` 等变量 |
| `template` | 模板相对路径（插件包 `templates/` 下），为空时按 `<目标文件名>.tmpl` |
| `mode` | 文件权限，默认 `0644`；含密钥建议 `0600` |
| `optional` | 模板缺失时不报错（默认 `false`） |

**渲染时机**：安装后、每次「保存配置」、每次「启动」前都会重新渲染，
保证「界面配置 = 实际配置文件」，不会出现改了一个地方忘记同步的情况。

### 2.3 docker 运行时

```json
"runtime": "docker",
"docker": {
  "image": "nginx:1.27-alpine",
  "ports": ["{{ .httpPort }}:80"],
  "volumes": ["{{ .platform.dataDir }}/conf:/etc/nginx/conf.d:ro"],
  "env": { "TZ": "Asia/Shanghai" },
  "network": "bridge",
  "restart": "unless-stopped",
  "command": ["nginx", "-g", "daemon off;"]
}
```

平台行为：`docker run -d --name devplat-<id> …`，停止用 `docker stop`，日志用 `docker logs --tail`，
卸载时 `docker rm -f`。设备未安装 docker 时，安装阶段就会给出明确提示。

## 3. schema：配置表单规范

平台按 `type` 自动渲染控件，无需插件提供前端代码。

| type | 控件 | 关键属性 |
| --- | --- | --- |
| `string` | 输入框 | `placeholder` `default` `required` |
| `password` | 密码框（可切换明文） | 同上；不会出现在日志里 |
| `int` | 数字框 | `min` `max` `default` |
| `bool` | 开关 | `default` |
| `select` | 下拉 | `options: [{label,value}]` |
| `textarea` | 多行文本 | `placeholder` |
| `list` | 可增删的子表单列表 | `fields: [子 schema]`、`default: [ {…} ]` |

公共属性：`key`（配置键，渲染模板时同名可用）、`label`（中文标签）、`help`（提示文案）。

**`list` 示例**（frp 的端口映射）：

```json
{
  "key": "proxies",
  "label": "端口映射",
  "type": "list",
  "fields": [
    { "key": "name", "label": "名称", "type": "string", "required": true },
    { "key": "localPort", "label": "本地端口", "type": "int", "min": 1, "max": 65535 }
  ],
  "default": [{ "name": "web", "localPort": 8090 }]
}
```

**校验规则**（平台内置）：
- `required` 为空 → 提示「配置项「X」不能为空」；
- `int` 超出 `min/max` → 提示范围；
- `select` 不在选项内 → 提示取值非法；
- 未在 schema 中声明的键会被忽略（不会被写回配置）。

## 4. 模板变量

配置文件模板与 `args` 都用 Go `text/template` 语法，可用变量：

| 变量 | 含义 |
| --- | --- |
| `{{ .platform.dataDir }}` | 插件数据目录（`<home>/plugin-data/<id>`） |
| `{{ .platform.installDir }}` | 插件包解压目录（`<home>/plugins/<id>/<version>`） |
| `{{ .platform.confDir }}` / `{{ .platform.logDir }}` | 配置目录 / 日志目录 |
| `{{ .platform.home }}` | 平台数据根目录 |
| `{{ .platform.pluginKey }}` / `{{ .platform.version }}` / `{{ .platform.arch }}` | 插件 id / 版本 / 架构 |
| `{{ .platform.platformURL }}` | 平台本机地址（插件回调平台接口时可用） |
| `{{ .<配置键> }}` | 用户在界面填写的任意配置项 |

可用函数：`split` / `join` / `trim` / `upper` / `lower` / `default` / `hasPrefix` / `replace` / `json`。

**示例**（`templates/frpc.toml.tmpl` 片段）：

```gotemplate
serverAddr = "{{ .serverAddr }}"
serverPort = {{ .serverPort }}
{{- if .authToken }}
auth.method = "token"
auth.token = "{{ .authToken }}"
{{- end }}

{{- range .proxies }}
[[proxies]]
name = "{{ .name }}"
type = "{{ .type }}"
localPort = {{ .localPort }}
{{- if eq .type "tcp" }}
remotePort = {{ .remotePort }}
{{- end }}
{{- end }}
```

## 5. 生命周期与平台行为

```
上传安装包 / 安装内置插件
   ↓ 校验 manifest（id、版本、架构、runtime、schema、路径穿越）
   ↓ 解压到 <home>/plugins/<id>/<version>/（限制文件数 5000、总量 512MB、禁符号链接）
   ↓ 建数据目录 <home>/plugin-data/<id>/{conf,logs}
   ↓ 生成默认配置（schema.default）
   ↓ 渲染 configFiles
状态：stopped（enabled=true, autoStart=true）
   ↓ 启动（每次启动前重新渲染配置）
状态：running（记录 PID / startedAt）
   ↓ 进程异常退出 → 按 restartPolicy 3 秒后自动拉起；日志落 logs/plugin.log（超 20MB 滚动一份）
   ↓ 停止（进程组 SIGTERM）/ 禁用（先停）/ 关闭自启
   ↓ 卸载（删包目录；数据目录默认保留，可选一并删除）
```

**平台保证**：
- 一个插件在设备上只有一个实例（多实例场景请用 `list` 配置项表达，或拆成多个插件 id）；
- 平台重启后：`running` 状态会被校准为 `stopped`，然后按 `autoStart` 重新拉起；
- 插件日志只保留「最近一份 + 一份历史」，设备磁盘有限。

## 6. 开发示例：从零写一个插件

以一个「定时上报心跳到远端 HTTP 接口」的插件为例：

**1) 写程序**（任意语言，能读配置、能长期运行、日志写 stdout 即可）

```go
// 读取 --config 指定的配置文件，循环上报，日志直接 fmt.Println
```

**2) 写 manifest.json**

```json
{
  "id": "heartbeat-agent",
  "name": "心跳上报",
  "version": "1.0.0",
  "vendor": "acme",
  "category": "device",
  "description": "按固定间隔把设备心跳上报到自建接口，断网自动重试。",
  "runtime": "process",
  "entry": "bin/heartbeat-agent",
  "args": ["--config", "{{ .platform.dataDir }}/conf/agent.json"],
  "restartPolicy": "always",
  "configFiles": [
    { "path": "{{ .platform.dataDir }}/conf/agent.json", "template": "agent.json.tmpl", "mode": "0600" }
  ],
  "schema": [
    { "key": "endpoint", "label": "上报地址", "type": "string", "required": true, "placeholder": "https://api.example.com/heartbeat" },
    { "key": "token", "label": "鉴权 Token", "type": "password" },
    { "key": "intervalSec", "label": "间隔(秒)", "type": "int", "default": 30, "min": 5, "max": 3600 },
    { "key": "deviceTag", "label": "设备标签", "type": "string", "default": "edge" }
  ]
}
```

**3) 写模板** `templates/agent.json.tmpl`

```gotemplate
{
  "endpoint": "{{ .endpoint }}",
  "token": "{{ .token }}",
  "interval": {{ .intervalSec }},
  "tag": "{{ .deviceTag }}",
  "dataDir": "{{ .platform.dataDir }}"
}
```

**4) 打包 + 安装**

```bash
bash scripts/pack-plugin.sh ./heartbeat-agent         # 产出 zip
# 页面：插件市场 → 上传插件包 → 填配置 → 保存 → 启动 → 看日志
```

## 7. 验收清单（提交插件前自查）

- [ ] `manifest.json` 在包根目录，`id` 全小写中划线，`version` 为 `x.y.z`
- [ ] `runtime=process` 时 `bin/` 内有对应架构可执行文件（arm 设备别放 amd64 二进制）
- [ ] 程序**前台运行**（不要 daemon 化、不要自己 fork 到后台），否则平台无法判断存活
- [ ] 日志输出到 stdout/stderr（平台负责落盘与滚动），不要自己写 syslog
- [ ] 所有可变数据写到数据目录（`{{ .platform.dataDir }}`），不要写系统目录
- [ ] 配置模板能被默认值成功渲染（默认值务必可跑通，避免「装完启动就崩」）
- [ ] 端口在 `ports` 中声明，避免与其他插件/平台端口（默认 8090）冲突
- [ ] 需要 root/特权的操作在 `privileged` 声明，并在 README 说明原因
- [ ] README 包含：用途、参数说明、常见故障与排查方法

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装报「manifest.json 解析失败」 | BOM/JSON 语法错误 | 平台已剥离 UTF-8 BOM；检查 JSON 合法性 |
| 安装报「插件不支持当前架构」 | `arch` 白名单不含设备架构 | 补齐 `arch` 或换对应二进制 |
| 启动报「可执行文件不存在」 | `entry` 路径错，或打包时漏了 `bin/` | 检查包内路径（区分大小写） |
| 启动后立即变 `error` | 程序前台退出（配置错/端口占用） | 看「日志」；日志里一般有明确报错 |
| 配置改了不生效 | 程序只在启动时读配置 | 保存配置时勾选「保存后立即重启」 |
| `exec format error` | 放错架构二进制 | 按 `uname -m` 重新编译 |
| docker 插件装不上 | 设备没装 docker 或服务没起 | `docker version` 检查；或关闭 `plugin.allow_docker` |

## 9. 发布到在线插件市场

平台支持「插件源」：一个提供索引 JSON 的 HTTP(S) 地址。发布流程：

### 9.1 打包并生成索引

```bash
# 1) 打包插件包（zip，manifest.json 在包根）
bash scripts/pack-plugin.sh plugins-src/my-plugin

# 2) 生成索引（--base-url 是插件包对外下载前缀）
python3 scripts/gen-plugin-index.py \
    --dir dist/plugins \
    --base-url https://plugins.example.com \
    --out dist/plugins/plugin-index.json \
    --key '<信任密钥>'
```

生成的索引结构：

```json
{
  "version": "1",
  "updatedAt": "2026-01-01T10:00:00+08:00",
  "plugins": [
    {
      "id": "frp",
      "name": "FRP 内网穿透",
      "version": "1.0.1",
      "category": "network",
      "description": "…",
      "icon": "ri:global-line",
      "runtime": "process",
      "arch": ["amd64", "arm64"],
      "downloadUrl": "https://plugins.example.com/frp-1.0.1.zip",
      "sha256": "<插件包 sha256，必填>",
      "sizeBytes": 12345678
    }
  ]
}
```

### 9.2 签名（推荐开启）

索引响应必须带请求头：

```
X-Index-Signature: hex(HMAC-SHA256(索引原始字节, 信任密钥))
```

平台侧在「插件源」里填写同一个密钥；校验失败时整批索引会被拒绝，并在源的「最近错误」里写明原因。
插件包还会按索引中的 `sha256` 二次校验，**索引不提供 sha256 时平台拒绝安装**。

### 9.3 升级与回滚

- **升级**：发布同 `id` 的更高 `version`，市场页会出现「升级」按钮；安装即覆盖（用户配置按 schema 合并保留）。
- **回滚**：把索引里的 `version`/`downloadUrl` 指回旧包，重新安装即可。
- 版本号必须是语义化 `x.y.z`，平台用数值段比较判断「可升级」。

### 9.4 发布清单

- [ ] 索引可 HTTPS 访问，且带 `X-Index-Signature` 头（若启用签名）
- [ ] 每个条目都有 `sha256` 与可访问的 `downloadUrl`
- [ ] `arch` 与实际二进制一致（arm 设备放 arm64/arm 包）
- [ ] 插件包内 `manifest.json` 的 `version` 与索引条目一致
- [ ] 先用「上传插件包」方式在真机验证一遍，再发布到索引

## 10. 平台对插件的安全约束（不可绕过）

1. 包内路径禁止 `..`、禁止绝对路径、禁止符号链接（防目录穿越）；
2. 解压文件数 ≤ 5000、总大小 ≤ 512MB；
3. `configFiles.path` 必须落在插件数据目录（含 `..` 直接拒绝）；
4. 插件进程以平台进程的用户运行（默认 `root`，可用 `install.sh --user` 降权）；
5. 插件**不能**直接修改平台数据库；如需读写平台能力，请通过平台开放接口（`/api/v1/open/*`）。
