# 部署运维手册

> 面向：实施/运维。覆盖安装、升级、备份、迁移、排障。
> 设计背景见《平台设计规划》，插件对接见《插件开发规范》。

---

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Ubuntu 20.04 / 22.04（其他具备 systemd + iproute2 的 Linux 亦可） |
| CPU 架构 | x86_64（amd64）/ arm64（aarch64）；armv7 需自行编译 |
| 内存 | ≥ 1GB（纯平台占用约 60～120MB） |
| 磁盘 | ≥ 2GB（含日志、插件与上传文件；数据库 10 万条日志约 30MB） |
| 权限 | root（下发路由/防火墙、抓包、改设备名需要） |
| 可选 | docker（安装容器型插件）、tcpdump（抓包排查）、chrony（NTP 校时） |

## 2. 安装

### 2.1 一键安装（推荐）

```bash
# 1) 上传两个文件到设备同一目录：device-platform-linux-arm64（或 amd64）、install.sh
chmod +x install.sh

# 2) 交互式安装（会依次询问安装目录、端口、运行用户、管理员密码）
sudo bash install.sh

# 2b) 或者全参数静默安装（适合出厂预装）
sudo bash install.sh -y \
  --dir /opt/device-platform \
  --port 8090 \
  --admin-password 'Admin@123456' \
  --user root
```

安装脚本做了什么：

1. 创建 `<dir>/{bin,conf,data,logs,plugins,plugins-bundled,plugin-data,storage,backup,run,tmp}`；
2. 安装二进制到 `<dir>/bin/device-platform`；
3. 生成 `<dir>/conf/config.yaml`（含随机 JWT 密钥、管理员初始密码，权限 600）；
4. 写入 `/etc/systemd/system/device-platform.service` 并 `enable`；
5. 启动服务、尝试放行防火墙端口（firewalld/ufw）。

安装完成后访问 `http://<设备IP>:8090`，用 `admin` + 初始密码登录。

### 2.2 参数一览

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--dir` | `/opt/device-platform` | 安装目录（也是数据根目录） |
| `--port` | `8090` | Web 端口 |
| `--admin-password` | 随机 | 初始管理员密码（仅首次初始化生效） |
| `--user` | `root` | 服务运行用户；非 root 时授予 CAP_NET_ADMIN/CAP_NET_RAW |
| `--service-name` | `device-platform` | systemd 服务名（同机多实例时区分） |
| `--binary` | 自动查找 | 指定二进制路径 |
| `--no-firewalld` | — | 不放行防火墙端口 |
| `--no-start` | — | 只安装不启动 |
| `--upgrade` | — | 升级：只换二进制，保留数据与配置 |
| `--uninstall [--purge]` | — | 卸载（`--purge` 连数据一起删） |

### 2.3 手工安装（理解原理用）

```bash
sudo mkdir -p /opt/device-platform/{conf,data,logs,plugins,plugin-data,storage}
sudo cp device-platform-linux-amd64 /opt/device-platform/bin/device-platform
sudo chmod +x /opt/device-platform/bin/device-platform
sudo /opt/device-platform/bin/device-platform -d /opt/device-platform      # 前台试跑，Ctrl+C 退出
sudo cp deploy/device-platform.service /etc/systemd/system/
sudo sed -i 's#__INSTALL_DIR__#/opt/device-platform#g; s#__RUN_USER__#root#g' /etc/systemd/system/device-platform.service
sudo systemctl daemon-reload && sudo systemctl enable --now device-platform
```

## 3. 构建与交付物

### 3.1 交叉编译（在开发机执行）

```bash
# Linux/macOS/WSL：前端 + 双架构二进制 + 插件包 → dist/
bash scripts/build-linux.sh

# 只重编后端（复用已有 web/dist）
bash scripts/build-linux.sh --skip-web

# 只编某一架构
bash scripts/build-linux.sh --skip-web --arch arm64
```

Windows 开发机：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1        # 仅本机 exe
# 交叉编译到 Linux 需在 WSL/GitBase 里用 bash scripts/build-linux.sh
```

产物：

```
dist/
├─ device-platform-linux-amd64
├─ device-platform-linux-arm64
├─ install.sh                    # 安装脚本
├─ device-platform.service       # systemd 模板
└─ plugins/frp-1.0.0.zip         # 内置插件包（放入 plugins-bundled 即出现在「可安装」）
```

### 3.2 Docker 方式（可选）

```bash
cd web && pnpm install && pnpm build && cd ..
docker build -f deploy/Dockerfile -t device-platform:1.0.0 .
docker run -d --name device-platform -p 8090:8090 \
  -v /opt/device-platform-data:/data --privileged device-platform:1.0.0
```

容器里管理网络/防火墙需要 `--privileged` 或 `--cap-add NET_ADMIN --cap-add NET_RAW`。

## 4. 日常运维

### 4.1 服务管理

```bash
systemctl status device-platform           # 运行状态
systemctl restart device-platform          # 重启（用户需重新登录：会话在内存）
systemctl stop device-platform             # 停止（会先停掉所有插件进程）
journalctl -u device-platform -n 200 -f     # 启动/崩溃日志
tail -f /opt/device-platform/logs/*.log     # 平台文件日志（页面「日志审计→系统日志」同源）
```

### 4.2 目录与文件

| 路径 | 内容 | 备份建议 |
| --- | --- | --- |
| `conf/config.yaml` | 全部配置（含 JWT 密钥） | ✅ 必备份 |
| `data/device-platform.db` | SQLite 数据库 | ✅ 必备份（见 §4.3 一致性备份） |
| `plugin-data/<id>/conf` | 插件配置（渲染结果） | ✅ 建议备份 |
| `plugins/` | 已安装插件包 | 可重装，建议备份 |
| `logs/` | 平台日志 | 按需 |
| `storage/` | 上传文件 | 按需 |
| `backup/` | 升级前的二进制备份 | — |

### 4.3 备份与恢复

```bash
# 一致性备份（SQLite 在线备份，不用停服务）
sqlite3 /opt/device-platform/data/device-platform.db ".backup '/opt/backup/dp-$(date +%F).db'"

# 或者整目录冷备（推荐停服务，避免 WAL 未合并）
systemctl stop device-platform
tar czf /opt/backup/device-platform-$(date +%F).tar.gz -C /opt device-platform
systemctl start device-platform

# 恢复
systemctl stop device-platform
rm -rf /opt/device-platform && tar xzf dp-2026-01-01.tar.gz -C /opt
systemctl start device-platform
```

### 4.4 升级

```bash
sudo bash install.sh --upgrade --binary ./device-platform-linux-arm64
```

升级只会替换 `<dir>/bin/device-platform`（旧二进制备份到 `backup/`），
数据库迁移在启动时自动执行（版本记录在 `schema_migrations` 表）。

**回滚**：

```bash
systemctl stop device-platform
cp /opt/device-platform/backup/device-platform.<时间戳> /opt/device-platform/bin/device-platform
systemctl start device-platform
# 若新版本已迁移数据库导致结构不兼容，需同时恢复 §4.3 的数据库备份
```

### 4.5 系统依赖包与可选能力

平台本体零外部依赖，但「下发类」功能需要对应的系统包与 systemd 服务。
页面上都有「安装依赖」按钮（内部就是 `apt-get install -y ...`），也可以提前装好：

| 能力 | 依赖包 | 系统服务 | 页面 |
| --- | --- | --- | --- |
| 网卡配置 / 网桥 / 端口聚合 | `netplan.io`（Ubuntu 自带） | systemd-networkd | 网络管理 → 网卡配置 / 网桥与聚合 |
| 静态路由 / 策略路由 | `iproute2` | —（直接写内核） | 网络管理 → 静态路由 / 策略路由 |
| DHCP 服务 / DNS 服务 | `dnsmasq` | dnsmasq | 网络管理 → DHCP 服务 / DNS 服务 |
| BGP / OSPF | `frr` `frr-pythontools` | frr | 网络管理 → 动态路由 |
| SNMP | `snmpd` `snmp` | snmpd | 设备管理 → SNMP 服务 |
| 防火墙策略 | `iptables` / `nftables`（按系统） | firewalld（可选） | 安全策略 → 防火墙 / 安全策略 |
| 带宽管理 | `iproute2`（tc） | — | 安全策略 → 带宽管理 |
| 抓包排查 | `tcpdump` | — | 设备管理 → 排查工具 |

注意事项：
1. **dnsmasq 与 systemd-resolved 抢 53 端口**：若 DNS 服务监听 `0.0.0.0` 且系统启用了 systemd-resolved（占用 127.0.0.53:53），
   请把监听地址改成具体网卡 IP，或按需关闭 resolved 的 stub listener。
2. **FRR 配置文件属主**必须是 `frr:frr`（平台写入时会自动 chown），否则 frr 启动会报权限错误。
3. **netplan 改动有失联风险**：平台会先 `netplan generate` 校验，失败自动回滚；仍建议先确认控制台/带外可用。
4. 所有下发都是**逐项回报**：失败的条目会带上系统原始错误（截断 400～600 字符），便于定位。

### 4.6 换机迁移

1. 老设备：`tar czf dp.tar.gz -C /opt device-platform`
2. 新设备：安装脚本装一遍（或解压覆盖），修改 `conf/config.yaml` 里的 `app.home`/端口；
3. 起服务，用原账号密码登录即可（数据库、插件、上传文件都在包内）。

### 4.7 在 WSL2 / 开发机上部署（验证用）

本平台在 WSL2 Ubuntu 上完整跑通过（Ubuntu 26.04、systemd 已启用）。要点：

1. **必须启用 systemd**：`/etc/wsl.conf` 里要有
   ```ini
   [boot]
   systemd=true
   ```
   否则 `install.sh` 的 `systemctl` 步骤会失败；改完执行 `wsl --shutdown` 再进。
2. **端口访问**：WSL2 默认把 `localhost` 转发到 Windows，装完直接在 Windows 浏览器打开
   `http://localhost:8090` 即可。
3. **依赖包可直接用页面上的「安装依赖」**，或先装好：
   ```bash
   sudo apt-get install -y dnsmasq tcpdump snmpd snmp dnsutils frr frr-pythontools
   ```
4. **不要随便 apply netplan**：WSL 的网卡由 Hyper-V 虚拟交换机管理，改网卡地址可能直接断网。
   验证 netplan 渲染是否合法，用「生成片段 + `sudo netplan generate`」即可（只校验不改网络）。
5. **dnsmasq 与 systemd-resolved**：resolved 占用 `127.0.0.53/127.0.0.54:53`。
   平台在「监听地址不是 0.0.0.0」时会自动加 `bind-dynamic`，避免抢通配地址；
   若坚持监听 `0.0.0.0`，需要先关掉 resolved 的 stub listener。
6. **DHCP 不要在生产网段随手开启**：WSL 的 NAT 网段上已有宿主 DHCP，验证完记得关掉（页面「启用 DHCP」开关 + 下发）。

**真机验证记录（WSL2 Ubuntu，2026-11）**：以下能力已实跑通过，不只是配置生成——
`ip rule` 策略路由下发与清理、`snmpwalk` 取到 sysDescr/sysContact/sysLocation、
`dig @127.0.0.1` 命中本地记录并成功上游转发、`dnsmasq --test` 语法通过、`tcpdump` 抓包、
`ping` 排查、`netplan generate` 校验通过、FRR 加载 BGP/OSPF 配置（`vtysh show running-config`）、
插件安装/启动/日志/`kill -9` 后自动拉起/停止、systemd 托管与开机自启。
期间修复了三个真机才暴露的问题：dnsmasq 未加 `bind-dynamic` 导致端口冲突、
`ip rule show` 优先级字段带冒号导致旧规则清理失效、apt 装完 FRR 后守护进程未自动开启。

## 5. 反向代理与 HTTPS（可选）

设备若对外提供访问，建议前置 Nginx 并启用 HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name device.example.com;
    ssl_certificate     /etc/nginx/ssl/device.crt;
    ssl_certificate_key /etc/nginx/ssl/device.key;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # 排查工具的流式输出（SSE）需要关闭缓冲
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

> 注意：`X-Forwarded-For` 透传后，访问日志/登录日志里才能看到真实客户端 IP。

## 5.1 插件在线市场（可选）

平台的插件有两种来源：**上传包**、**在线索引**。启用在线市场需要一台能提供索引 JSON 的 HTTP(S) 服务：

```bash
# 1) 打包插件（每个插件目录一个 zip）
bash scripts/pack-plugin.sh plugins-src/frp

# 2) 生成索引（downloadUrl 按实际部署地址填；--key 用来算签名）
python3 scripts/gen-plugin-index.py --dir dist/plugins \
    --base-url https://plugins.example.com --out dist/plugins/plugin-index.json --key '<信任密钥>'

# 3) 发布：把 dist/plugins 放到静态服务上，并在索引响应里加头
#    X-Index-Signature: <生成脚本打印的 HMAC-SHA256 十六进制串>

# 4) 平台侧：插件市场 → 插件源 → 新增（填索引地址 + 信任密钥，启用）
#    然后「插件市场 → 在线市场」即可看到插件并一键安装/升级
```

本地联调可以用自带的小服务器（自动加签名头）：

```bash
MARKET_KEY='<信任密钥>' python3 scripts/market-index-server.py dist/plugins 18080
# 插件源地址填 http://127.0.0.1:18080/plugin-index.json ，密钥同上
```

安全说明：配置了信任密钥后，索引**必须**带正确签名，否则整批拒绝；
每个插件包还必须与索引里的 `sha256` 一致，不一致直接取消安装。

## 6. 排障手册

### 6.1 服务起不来

```bash
journalctl -u device-platform -n 100 --no-pager
```

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `bind: address already in use` | 端口被占用 | `ss -tunlp \| grep 8090` 找进程，或改 `--port` |
| `jwt.secret 不能为空` | 配置缺 JWT 密钥 | 在 `conf/config.yaml` 填 ≥32 位随机串 |
| `数据库迁移失败` | 数据库文件损坏/权限 | 检查 `data/` 权限；从备份恢复 |
| `creating data root 失败` | 安装目录权限 | `chown -R <user> <dir>` |

### 6.2 页面能开但接口 401/403

- 401：会话失效（重启服务导致），重新登录即可；
- 403：当前账号缺少权限码，用超管在「系统设置 → 角色管理」给角色勾选对应菜单/按钮。

### 6.3 下发类操作失败（路由/NAT/QoS/防火墙）

页面会逐条显示失败原因，常见：

| 提示 | 处理 |
| --- | --- |
| `需要 root 权限` | 用 `install.sh --user root` 重装，或 `systemctl edit` 添加 capability |
| `系统缺少 ip 命令（iproute2）` | `apt install iproute2` |
| `当前运行环境为 windows，暂不可用` | 该类功能仅 Linux 支持（开发机功能受限是预期行为） |
| `iptables: Permission denied` | 同上，需 root 或 CAP_NET_ADMIN |
| `系统未安装 dnsmasq` / `未安装 FRR` / `未安装 snmpd` | 点对应页面的「安装依赖」，或手动 `apt-get install -y dnsmasq frr snmpd` |
| netplan 下发失败并提示已回滚 | 看返回的 `netplan generate` 原始报错，常见为成员网卡仍带地址、或 YAML 缩进/键名错误 |
| dnsmasq 起不来（端口被占） | `ss -tunlp \| grep :53` 看占用者；systemd-resolved 的 stub 需改监听地址或禁用 |
| FRR 起不来 | `journalctl -u frr -n 50`；确认 `/etc/frr/daemons` 里 bgpd/ospfd 为 yes，`/etc/frr/frr.conf` 属主 frr:frr |
| 在线插件市场为空且提示索引获取失败 | 检查「插件源」地址可达性、签名密钥是否与发布端一致（错误会写在源的「最近错误」里） |

### 6.4 插件问题

| 现象 | 处理 |
| --- | --- |
| 插件状态 `异常` | 打开「日志」看退出原因；常见为配置错、端口占用、缺依赖 |
| 日志为空 | 程序没往 stdout/stderr 输出；检查是否自行 daemon 化 |
| 配置保存后没生效 | 保存时勾选「保存后立即重启」 |
| 重启平台后插件全停 | 检查插件「自启」开关与 `plugin.auto_start` 配置 |

### 6.5 磁盘占用偏高

```bash
du -sh /opt/device-platform/* | sort -h        # 定位大户
```

常见来源与处理：
- `logs/`：日志保留天数由 `log.max_age_days` 控制，`max_size_mb` 控制单文件；
- 数据库：日志类表按 `system.log_retain_days`（默认 30 天）自动清理，由后台任务每小时执行；
- `plugin-data/`：某些插件自身会写数据（如缓存、模型文件），按插件 README 清理；
- `tmp/`：插件安装临时目录，异常中断可能有残留，可安全清空。

## 7. 安全加固建议

1. **改默认密码**，并开启验证码（站点设置里）；
2. 只在内网/管理网开放 8090，对外一律走 HTTPS + 反向代理；
3. 关闭不需要的能力：`system.tools_enabled=false`（排查工具）、`scheduler.shell_enabled=false`（Shell 定时任务）、`plugin.allow_docker=false`；
4. 定期备份 `conf/` 与 `data/`，并把备份文件拉到异机；
5. 审计入口：日志审计 → 访问日志（谁访问了什么）、操作日志（谁改了什么，含字段 diff）、登录日志（谁在什么时候登录/失败）；
6. 服务运行用户非 root 时，部分下发能力不可用——按现场需要权衡。
