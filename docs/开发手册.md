# Web Basic Admin · 开发手册

> 面向二次开发者：讲清楚「代码怎么组织、约定是什么、加功能改哪里」。
> 只讲使用不谈原理请看 [操作手册](./操作手册.md)。

---

## 1. 这是什么

一个**开箱即用、可长期维护**的后台管理脚手架：后端 Go + Gin + GORM，前端 Vue 3 + Web Admin Pro，单可执行文件部署。

已经内置的能力：

| 分类 | 内容 |
| --- | --- |
| 权限体系 | 用户 / 角色 / 菜单（目录·页面·按钮·接口四类权限点）/ 部门 / 岗位 / 数据权限 / 多租户 |
| 工作台 | 4 张统计卡片 + 「我的待办 / 我的消息 / 通知公告」页签，顶栏铃铛实时未读 |
| 系统设置 | 站点个性化（名称 / logo / 登录页文案 / 注册开关 / 验证码 / 滑块）、字典、参数、租户、文件、定时任务、代码生成 |
| 通知与协作 | 通知公告（发布扇出站内信）、站内信、待办；支持业务系统通过开放接口推送 |
| 安全 | JWT + 双 token 静默刷新、图形验证码、滑块校验、登录失败锁定、强口令策略、字段级操作日志 |
| 运维 | 健康检查、Prometheus 指标、结构化日志、内嵌数据库迁移、单二进制 / Docker Compose |

技术栈版本：Go 1.22+ / Gin / GORM / MySQL 8 / Redis 7；Vue 3.5 / TypeScript / Vite 7 / Pinia / Tailwind 4 / Element Plus 2。

## 2. 目录结构

```
web-basic/
├─ cmd/server/            # 入口（读配置 → 迁移 → 装配 → 起服务）
├─ configs/config.yaml    # 默认配置（环境变量 APP__XXX__YYY 覆盖）
├─ internal/
│  ├─ api/                # HTTP 处理层：参数绑定 + 调 service + 统一响应
│  ├─ service/            # 业务逻辑（唯一允许写业务规则的地方）
│  ├─ repository/         # 数据访问（GORM）
│  ├─ model/entity/       # 表结构映射
│  ├─ router/             # 路由注册 + 权限码声明
│  ├─ middleware/         # 鉴权 / 权限 / 限流 / 审计 / 指标 / 开放接口 Key
│  ├─ migrate/            # 迁移执行器（内嵌 migrations/*.up.sql）
│  ├─ openapi/            # 在线接口文档（/swagger）
│  └─ webui/              # 内嵌前端产物（web/dist）
├─ migrations/            # 数据库迁移（唯一建表/种子来源）
├─ pkg/                   # 通用库：crypto / jwt / errs / response / captcha / id / storage
├─ scripts/               # 构建、图标子集、E2E（零依赖 CDP）
└─ web/                   # 前端（Vue3 + Web Admin Pro）
   ├─ src/api/            # 接口层（成功提示文案也定义在这里）
   ├─ src/views/          # 页面（system / monitor / dashboard / auth / exception）
   ├─ src/components/core # 框架组件（表格、表单、布局、通知等）
   ├─ src/utils/          # http / upload / password / site 等工具
   └─ src/locales/        # 文案（当前只交付中文，见 §5.6）
```

## 3. 快速开始

### 3.1 本地开发

```bash
# 1) 基础设施（MySQL 3307 / Redis 6380 可用 docker 起）
docker compose -f deploy/docker-compose.yml up -d mysql redis

# 2) 后端（:8090，首次启动自动建表 + 初始化数据 + 建超管）
APP__APP__ADMIN_PASSWORD=Admin@123456 go run ./cmd/server -c configs/config.yaml

# 3) 前端（:5173，代理到 8090）
cd web && pnpm install && pnpm dev
```

默认账号 `admin`，密码取 `APP__APP__ADMIN_PASSWORD`（未设置时按配置生成，见启动日志）。

### 3.2 生产（单二进制 / Docker）

```bash
# 单二进制：前端产物先构建，再打包进二进制
cd web && pnpm build && cd ..
powershell -ExecutionPolicy Bypass -File scripts/build.ps1            # Windows
# 或：make build

# Docker（前后端一体镜像 + MySQL + Redis）
docker compose -f deploy/docker-compose.yml up -d --build
```

常用环境变量（viper 前缀 `APP__`，层级用 `__` 分隔）：

| 变量 | 说明 |
| --- | --- |
| `APP__APP__PORT` / `APP__APP__MODE` | 端口 / `debug`·`release` |
| `APP__MYSQL__DSN` | 必须带 `parseTime=True&clientFoundRows=true` |
| `APP__REDIS__ADDR` | Redis 地址 |
| `APP__JWT__SECRET` | ≥32 位随机串（生产必改） |
| `APP__APP__ADMIN_PASSWORD` | 初始化超管密码 |
| `APP__STORAGE__TYPE` | `local` 或 `oss` |
| `APP__STORAGE__OSS__DIRECT_UPLOAD` | 是否允许前端直传（默认开启） |
| `APP__SCHEDULER__SHELL_ENABLED` | 是否允许 Shell 脚本型定时任务（默认关闭） |
| `APP__INTEGRATION__ENABLED` / `__API_KEY` | 开放接口开关与密钥（默认关闭） |

## 4. 后端约定

### 4.1 分层与调用方向

```
router → api → service → repository → MySQL/Redis/Storage
```

- **api**：只做绑定、校验（`binding` tag）、调用 service、`response.Ok/OkData/Page/Fail`。
- **service**：业务规则全部在这里；错误用 `errs.Invalid("原因")` / `errs.ErrNotFound` 等语义错误。
- **repository**：纯数据访问；`repository.Result` 把「影响行数=0」翻译为 `ErrRecordNotFound`。
- **entity**：字段与表一一对应，`json` tag 与前端契约一致；雪花 ID 一律 `,string` 下发。

### 4.2 新增一个功能的完整路径

以「待办」为例，照着做即可：

1. `migrations/0000NN_xxx.up.sql`：建表 + 菜单 + 按钮权限 + 角色授权（见 §4.3）。
2. `internal/model/entity/xxx.go`：结构体 + `TableName()`。
3. `internal/service/xxx.go`：入参/出参结构 + 业务方法（校验、租户过滤、幂等）。
4. `internal/api/xxx.go`：处理器，`principal.Must(c)` 取当前用户。
5. `internal/router/router.go`：注册路由，写清权限码 `middleware.Perm("模块:资源:动作")`。
6. `web/src/api/xxx.ts`：接口封装，顺带定义成功提示文案（§5.8）。
7. `web/src/views/...`：页面；`web/src/types/api/web-basic.d.ts`：类型。
8. `scripts/e2e-api.mjs` / `e2e-smoke.mjs`：补断言。
9. 文档：本文 §4/§5 与操作手册对应章节。

### 4.3 数据库迁移（唯一的建表来源）

- 位置 `migrations/NNNNNN_name.up.sql`，用 `//go:embed *.up.sql` 打进二进制，启动时按序执行。
- 执行记录在 `schema_migrations(version, name, applied_at)`，**同一版本只执行一次**。
- 编写规则：
  - 建表用 `CREATE TABLE IF NOT EXISTS`、种子用 `INSERT IGNORE`；
  - MySQL 不支持 `ADD COLUMN IF NOT EXISTS`，这类 DDL 就靠版本表保证只跑一次；
  - **不要修改已发布的迁移**，结构变更一律新增文件。
- 当前迁移清单：

| 版本 | 内容 |
| --- | --- |
| 000001 | 基础表结构（用户/角色/菜单/部门/日志/文件/配置…） |
| 000002 | 种子数据（超管、角色、菜单树、按钮权限、内置参数） |
| 000003 | 工作台菜单 |
| 000004 | 菜单结构与图标规范化 |
| 000005 | 个人中心菜单 |
| 000006 | 操作日志字段级 diff 列 |
| 000007 | 通知公告 + 站内信 |
| 000008 | 数据导出菜单与权限 |
| 000009 | 代码生成菜单与权限 |
| 000010 | 站点个性化配置 + 菜单 |
| 000011 | 登录交互开关（验证码 / 滑块）参数 |
| 000012 | 待办与通知已读表、站内信幂等键、菜单英文名、消息与待办菜单 |

### 4.4 种子数据与菜单

- 菜单表 `sys_menu` 同时承载「路由 + 权限点」：`type` 1=目录 2=页面 3=按钮 4=接口。
- 页面权限码形如 `system:user:list`，按钮形如 `system:user:create`；超管 `*:*:*` 隐式拥有全部。
- `name` 中文、`name_en` 英文（前端按语言取值，缺省回落中文）。
- 新增菜单后要让前端「菜单管理」可见，需给对应角色授权（`sys_role_menu`）。

### 4.5 统一响应与错误处理（面向用户可读）

响应体固定 `{ code, message, data, traceId }`，`code=0` 成功。

**一条硬约定：业务原因必须直说，不能让用户看到「服务器内部错误」。**

| 场景 | 写法 |
| --- | --- |
| 用户输入/业务规则不满足 | `errs.Invalid("密码还需要包含：大写字母")` 或 `errs.InvalidErr(err)` |
| 参数绑定失败 | `response.BindErr(err)`（已把 validator 错误翻译成中文：字段 + 规则） |
| 记录不存在 / 重复 / 被引用 | `errs.ErrNotFound` / `errs.ErrDuplicate` / `errs.ErrRecordUsed` |
| 数据库/系统故障 | `errs.ErrDB.WithErr(err)` / `errs.ErrInternal.WithErr(err)`（前端只见通用文案） |

前端 `utils/http/error.ts` 的 `handleError` **优先展示后端 `message`**，拿不到业务消息才回落状态码文案。

### 4.6 鉴权、权限、租户、开放接口

- 登录成功后签发 access + refresh 双 token；401 时前端静默刷新并重放请求。
- 鉴权中间件从 Redis 读会话，`principal.Must(c)` 提供 `UserID/TenantID/Perms/DataScope`。
- 数据权限：全部 / 本部门 / 本部门及以下 / 仅本人 / 自定义部门，查询统一用 `scope.Tenant` + 数据范围。
- 开放接口：`/api/v1/open/*` 用 `X-API-KEY`（`middleware.APIKey`），未配置密钥时整体 404，见 §9。

### 4.7 审计、指标、接口文档

- 操作日志：`middleware.OperLog` 记录请求、耗时、结果，并对关键实体做**字段级 diff**。
- 指标：`/metrics`（Prometheus 文本格式，含 MySQL/Redis 探针）。
- 健康检查：`/healthz`（存活）、`/readyz`（依赖就绪）。
- 接口文档：`/swagger`（根据路由与注解自动生成 OpenAPI）。

## 5. 前端约定

### 5.1 启动顺序（踩过坑，勿改）

```ts
initStore(app)          // 必须先装 pinia：http 拦截器里的 useUserStore 依赖它
await initSiteConfig()  // 再拉站点配置，保证登录页首帧就是配置后的名字/文案
initRouter(app) → setupGlobDirectives → app.use(i18n) → mount
```

### 5.2 路由（后端菜单驱动）

`VITE_ACCESS_MODE=backend`：登录后 `GET /api/v1/auth/routes` 拿到路由树，`ComponentLoader` 按 `component` 字段
动态导入 `src/views/**/*.vue`（`system/user/index` → `/system/user`）。前端不再维护菜单清单。

### 5.3 页面与权限

- 按钮用 `v-auth="'system:user:create'"`，超管自动放行。
- 列表统一 `useTable` + `ArtTable` + `ArtTableHeader`；**不要给 `ArtTable` 硬编码 `:stripe`**，
  否则顶栏「表格设置」的斑马纹开关会失效。
- 双栏页面（如字典）：左侧导航用轻量表头，`ArtTableHeader` 只给真正的表格用。

### 5.4 站点个性化配置

`utils/site.ts` 在启动时拉 `/public/site-config`，提供 `siteConfig` 响应式对象；
后台「系统设置 → 站点设置」保存后调用 `applySiteConfig` 立即生效（标题 / logo / 登录页 / 注册开关）。

### 5.5 工作台（待办 / 消息 / 通知）

- 页面：`views/dashboard/workbench/index.vue`，顶部 4 张统计卡片 + 一个页签卡片。
- 接口：`/api/v1/my/summary`、`/api/v1/my/todos*`、`/api/v1/my/notices*`、`/api/v1/messages*`。
- 后端强制 `tenant_id + user_id` 过滤，**不接受前端传用户 ID**。
- 顶栏铃铛 `art-notification` 读同一批接口，点击跳 `/dashboard?tab=todo|message|notice`。

### 5.6 主题、多语言、图标

- 主题：`settingStore` 管明暗/主题色/菜单布局；`ArtTable` 的密度、斑马纹等走 `tableStore` 全局状态。
- **多语言：当前只交付中文**。`headerBar.language.enabled=false`、`setting.showLanguage=false`、
  `getDefaultLanguage()` 固定返回中文；`zh.json`/`en.json`、Element Plus locale、菜单 `name_en` 都保留，
  需要恢复时把这三处改回来即可。
- 图标：使用 Iconify 名称（`ep:xxx` / `ri:xxx`），**离线子集**由 `scripts/gen-icon-subset.mjs` 生成；
  新增图标（含迁移里菜单用到的）后必须重新生成再构建。

### 5.7 统一文件上传

`web/src/utils/upload/index.ts` 的 `uploadFile(file, { bizType })` 是唯一入口：

1. 后端支持直传时（`sys.upload.direct=true`）：申请签名 → 浏览器直传 OSS → 回执落库；
2. 否则或直传失败：自动回退 `POST /files/upload` 中转上传。

OSS 侧需要配置 CORS（允许站点域名 PUT + Content-Type 头）。对象键统一为
`年/月/日/[业务]/日期时间-雪花ID.扩展名`。

### 5.8 提示与弹窗约定

- **成功提示集中在接口层**：在 `src/api/*.ts` 里写 `successMessage: '保存成功'`，页面不要再弹一次。
- 失败提示由 `handleError` 统一处理并优先展示后端业务消息。
- 文案与规则要「可读、可执行」：例如密码规则由 `/public/password-policy` 下发，页面常显。

## 6. 密码策略

- 规则（`pkg/crypto.CheckStrength`）：长度 ≥ `auth.pwd_min_len`（且不小于 8）、必须同时包含大写/小写/数字、
  禁常见弱口令、禁 3 个及以上连续相同字符。
- 对外暴露：`GET /api/v1/public/password-policy` → `{minLength, requireUpper, requireLower, requireDigit, description}`。
- 前端一致校验：`web/src/utils/password.ts` 的 `checkPassword()` / `passwordValidator()`（blur 即提示）。
- 覆盖位置：个人中心改密、用户管理重置密码（留空自动生成强密码）、注册页。
- 改密成功后该账号所有会话立即失效。

## 7. 文件存储

| 模式 | 配置 | 说明 |
| --- | --- | --- |
| 本地磁盘 | `storage.type=local` | 落盘 `storage/`，通过 `/static` 访问 |
| 阿里云 OSS | `storage.type=oss` | 支持私有读 + 签名 URL；`direct_upload=true` 时浏览器直传 |

- 统一限制：`upload.max_size_mb`（默认 20MB）、`upload.allow_ext` 白名单、危险 MIME 检测、SHA-256 去重记录。
- 直传回执会校验对象键规则（必须是我们生成的 `年/月/日/...` 结构），可选用 `verify_exists` 做 HEAD 校验。

## 8. 定时任务

| job_type | 类型 | 执行内容 | 场景 |
| --- | --- | --- | --- |
| 1 | 内置处理器 | 代码里的 `JobHandlers` 注册表 | 清理会话/日志/临时文件等维护任务 |
| 2 | HTTP 调用 | `target` + 方法 + 参数 | 触发第三方 webhook |
| 3 | Shell / 脚本 | `params={"interpreter":"sh|bash|python3","script":"…"}` | 自定义运维脚本，改脚本不用发版 |

- 调度：6 段 cron（秒 分 时 日 月 周），`GET /system/jobs/meta` 下发可用类型与处理器清单。
- Shell 型安全闸：`scheduler.shell_enabled` 总开关（默认关闭）、解释器白名单、按 `timeout_sec` 强制超时并杀进程组、
  输出截断后写执行日志。
- 多副本部署依赖 Redis 租约，保证同一时刻只有一台执行。

## 9. 对接契约（业务系统 → 本系统）

业务系统把「消息 / 待办」推进来，无需用户登录：

```bash
APP__INTEGRATION__ENABLED=true
APP__INTEGRATION__API_KEY=<32 位以上随机串>
APP__INTEGRATION__TENANT_ID=1
```

```bash
# 推送站内信（userIds 为空 = 全员，仅后台手工接口允许）
curl -X POST http://host:8090/api/v1/open/messages \
  -H 'X-API-KEY: <key>' -H 'Content-Type: application/json' \
  -d '{"userIds":["2118xxx"],"title":"审批通过","content":"…","type":1,"bizType":"order","bizKey":"order-1001-approve"}'

# 派发待办
curl -X POST http://host:8090/api/v1/open/todos \
  -H 'X-API-KEY: <key>' -H 'Content-Type: application/json' \
  -d '{"userId":"2118xxx","title":"处理订单 1001","priority":3,"dueTime":"2026-01-31 18:00:00","linkUrl":"/order/1001","bizKey":"order-1001-task"}'
```

- 雪花 ID 必须用**字符串**传（JS 数字只有 53 位精度）；服务端对 `["123"]` / `[123]` 都兼容。
- `bizKey` 是幂等键：同租户内重复推送只落一条，业务系统可安全重试。
- 主体固定为「系统账号」：只能写目标用户的数据，不能读取任何用户数据。
- 后台「系统设置 → 消息与待办」可手工推送，也可作为联调入口。

## 12. 硬约定与已知坑

1. **迁移是唯一建表入口**：不要用 GORM AutoMigrate 建业务表；不要改已发布的迁移文件。
2. **雪花 ID 一律字符串**：JSON 出参用 `,string`，否则前端 JS 会截断 19 位 ID（本项目已踩过一次）。
3. `clientFoundRows=true` 不能省：否则「影响行数=0」无法区分「无变化」与「记录不存在」。
4. 前端启动顺序不能改（§5.1）：`initStore` 必须在 `initSiteConfig` 之前。
5. 表格页不要硬编码 `:stripe`；否则全局斑马纹开关失效。
6. 成功提示只写一处（接口层）；页面重复弹窗会让用户以为操作执行了两次。
7. 业务错误用 `errs.Invalid`，不要把内部错误文本直接抛给用户。
8. 新增图标必须跑 `node scripts/gen-icon-subset.mjs`，再 `pnpm build`，最后 `scripts/build.ps1 -SkipWeb`。
9. 会话缓存与在线用户依赖 Redis；清空 Redis 会让所有用户重新登录（属于预期行为）。
10. 删除角色/菜单前先想清楚关联：被引用会返回 `ErrRecordUsed`，而不是级联删除。
